    2. New API for the future mobile profile screen
    

    GET /api/v1/ap-easy/QuotationProfile
X-Token: <current-user-token>
Accept: application/json

    

    Mobile UAT URL: https://uat-api.apdigital.ai/api/v1/crm-ap/ap-easy/QuotationProfile. Mobile sends Authorization: Bearer <customer-token> to the gateway; the gateway forwards X-Token to Easy. Direct local/internal requests use X-Token.
    

    This endpoint accepts no query parameters or request body. Authentication middleware obtains userId and phone_number through token introspection. The service uses that authenticated phone to call CRM; quotation access does not check MongoDB phoneVerified. No booking, active resident unit or CRM contact mapping is required.

    The four customer keys are always present. Customer strings and nulls are preserved as received from CRM, including surrounding whitespace. Thai and English names are supported.     A successful empty list keeps the normal manual profile form. Null customer fields within a returned quotation are valid CRM values; they do not mean the quotation is missing. Duplicate quotation identities, missing/null customer objects or invalid customer field types return an upstream error instead of a misleading empty success.

    Success responses keep CRM requestID and message. Responses use Cache-Control: no-store and Pragma: no-cache.
    

    3. Profile form and save rules
    

    Read the account with GET /api/v1/users/me/profile and call QuotationProfile alongside it. Preserve existing account values and fields already edited by the customer.
    

    With one quotation, use its customer fields as suggestions for missing, untouched form fields. With several quotations, show their customer data for review and let the customer confirm which customer details to use, or enter the names manually. Do not silently choose a first/latest quotation or combine names from different quotations. Customer data selection only prepares the form; it does not persist activeQuotation or change resident access.

    Apply the app's existing form validation. A late API response must not overwrite manual edits. After confirmation, save through the existing asset API, including all fields required by the real onboarding form. Minimal name-only example:
    

    PUT /api/v1/users/me/profile
X-Token: <current-user-token>
Content-Type: application/json

{"firstName":"Jane","lastName":"Example"}

    

    The profile write uses phone; the quotation customer uses phoneNumber. Contact changes still use the existing phone/email verification flow. Do not copy the entire customer object into the profile write or set verified flags from CRM data. Avatar, identity documents and other missing fields still come from the account or customer input. Continue only after a successful save; on failure retain the form and entered values.

    After discovery returns exactly one quotation, mobile uses that returned document triple in the selection request, waits for success, reads TimelineDetails using project and unit (Easy resolves the saved activeQuotation), and opens the timeline directly. No quotation-list click is needed in this case. If there are several quotations, show a chooser and continue with the chosen triple. The backend does not select a quotation during the profile read or profile save.
    

    Wait for successful selection before treating it as saved. A 403 means the selected quotation is unavailable to this customer; refresh discovery. If selection fails, keep the saved profile, show an entry/selection error, and allow retry. Do not call the legacy unit-only timeline as a fallback. Do not mutate the local resident active unit while waiting. A timeline read failure shows a retry state on the intended timeline screen; it does not undo the profile save.
    

    For the full document, find data[projectNo].units[unitNo].quotations[header.quotationNo] by matching the three values, not numeric array indexes. A zero/first/latest entry is not a substitute for the selected quotation.

    5. Booking, existing customers and resident access
    

    CRM saves a booking and publishes topic quotation-unit, body key:CREATE_BOOKING. notification-service persists the event, maps supported contact identities and links the exact quotation in the shared database. Easy reads that link. Mobile refreshes discovery/timeline on the normal refresh or app-resume policy. A mobile push/subscription was not added.
    

    


    
Timeline condition
Display

Quotation current; Booking upcoming

Booking-link-pending state; no guessed booking

    

    
Durable authorized booking saved, CRM read lagging
Quotation completed; booking details pending

    

    
Exact booking and CRM timeline ID verified
Quotation completed, booking and later stages from verified timeline

    

    
Full timeline booking ID missing/mismatched
Safe partial quotation + booking summary; exclude later stages

    

    

    Read bookingLinkStatus and message to handle partial results. A linked purchase still does not grant resident services. Existing residents keep their active resident unit while browsing another quotation. Existing AP Easy customers retain existing booking/property data. Completed profiles are not forced through the non-resident form again.
