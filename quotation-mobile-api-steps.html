Mobile API connection steps

Updated 11 November 2026 · Agreed automatic quotation flow. Backend code is prepared; deploy and complete UAT acceptance before mobile release. Read the full mobile contract.

1. Required journey

Not logged in → Login / OTP / consent → “ฉันไม่ใช่ลูกบ้าน” → Fill and save profile → Automatic quotation → Smart World home timeline.

No quotation chooser. No QuotationSelection call is required. Keep every quotation, but show one active timeline. Existing customers keep their active property; customers without an active unit start at the latest quotation.

Customer condition Backend action
Existing active unit, including an AP Easy unit with zero IDs Keep that unit. Select the latest quotation for the same project/unit.
No active unit Select the latest quotation overall and save its project/unit as active.
Active unit has no matching quotation Keep the unit; return activeQuotation: null. Keep the normal home.
No quotations Keep existing assets and active unit; return an empty discovery.

“Latest” uses quotationDate, not the array order, document number or update time. Valid dates rank before missing/invalid dates. Equal dates use ascending project, unit and quotation references as a stable tie-break. If all dates are missing/invalid, the same tie-break is used; this is a fallback, not a claim that one document is newer. CRM dates are returned unchanged.

    4. Requests and response examples
    

    Mobile quotation base: https://uat-api.apdigital.ai/api/v1/crm-ap/ap-easy. Use the existing asset gateway route for the asset service. Mobile sends Authorization: Bearer <customer-token>; direct/internal service calls use X-Token.
    

    Before saving the profile
    

    curl --request GET \
  'https://uat-api.apdigital.ai/api/v1/crm-ap/ap-easy/QuotationProfile' \
  --header 'Authorization: Bearer <customer-token>'

    

    No phone, quotation reference, body or query is needed. Middleware supplies the authenticated phone. Names are per quotation at data.quotations[i].customer:
    

    {
  "data": {
    "hasQuotations": true,
    "quotationCount": 2,
    "quotations": [
      {
        "projectNo": "P1", "unitNo": "U1", "quotationNo": "Q1",

      }
    ]
  },
  "requestID": "synthetic-trace",
  "message": "Success"
}

    

    Keep existing account values and manual edits. With several customer records, leave the form available for manual entry. Automatic timeline selection does not automatically select an account name.

    Then refresh the existing asset endpoint. The response adds hasQuotation on property cards and the active unit. Saved cards remain visible during empty/unavailable lookup; hasQuotation stays false until a current successful match.
    

    Open the selected timeline
    

    curl --request GET \
  'https://uat-api.apdigital.ai/api/v1/crm-ap/ap-easy/TimelineDetails?projectNo=P2&unitNo=U2' \
  --header 'Authorization: Bearer <customer-token>' \
  --header 'Accept-Language: en'

    

    Use the actual activeQuotation.projectNo and .unitNo. Do not send a phone or require quotationNo. The backend looks up the latest authorized quotation for the requested project/unit using the authenticated phone. A saved selection is not required for this lookup. Quotation is Step 1, followed by all existing property timeline rows. QuotationJourneys is a root JSON object; profile has the shown CRM envelope; asset APIs retain their existing status/data envelope.
    

    Quotation is added before the existing property timeline. Keep every existing row and its dates, status, state, color and inspection details. For a horizontal project the usual order is Quotation → Booking → Contract → Loan → Inspection → Transfer. Vertical projects keep the existing Installment row; cash buyers keep the existing rule that omits Loan. Kafka booking-link metadata does not decide which property rows are visible. When there is no booking data yet, the normal later stages remain Upcoming with null dates/statuses. Existing currentStatus, propertyType and message are preserved when the property journey has started; before it starts, Quotation is current.

Keep normal home. Do not open another property's quotation or show a chooser.

    No new users.apEasy contact mapping is created from quotations. Existing mapping is preserved. The notification-service Kafka consumer handles CREATE_BOOKING after CRM saves a booking. Mobile does not call Kafka or create booking records through this feature.
    

    6. Handoff and UAT checklist
    

    The backend stores all current quotation references, deduplicates assets per property, and saves the selected reference with any new active unit in one conditional user update. Repeated requests do not duplicate assets. Existing zero-ID AP Easy active units are valid and are matched by project/unit references.
    

    Test new customer with two dates, existing matching unit, existing unmatched unit, multiple quotations on one property, zero-ID active unit, no quotation, unavailable CRM, failed profile save, repeat calls and booking saved. The normal automatic mobile flow uses three Easy GET endpoints: Profile, Journeys and Timeline; Details is optional. The legacy selection endpoint remains supported for explicit context switches.
    

    Deploy AP Easy and asset-management changes together for the new fields. For the complete asset response shown here, enable QUOTATION_DISCOVERY_ENABLED=true with the existing internal Easy base URL. Without it, asset discovery fields are not populated; keep the successful direct Journey response rather than treating an asset hasQuotation: false as no quotation. Direct mobile QuotationJourneys works independently of that flag. Confirm gateway forwarding and UAT behavior before release. The public documentation is ready to share; backend deployment and live acceptance are separate release steps.
    

    No quotation: keep Step 1 as Upcoming
    

    For an existing property, TimelineDetails always returns Quotation first. A confirmed no-match returns this placeholder, then every original property row:
    

    {
  "key": "quotation",
  "label": "ใบเสนอราคา",
  "date": null,
  "status": null,
  "state": "upcoming",
  "colorCode": "#F6F6F6"
}

    

    quotationNo is omitted because no document exists. The placeholder stays Upcoming even when Booking or later stages already have progress. Existing dates, statuses, inspection details, currentStatus, propertyType and message stay unchanged. The UI uses state: "upcoming"; status remains null, matching the existing upcoming-item contract.
    

    A null activeQuotation does not hide an existing home's timeline. Keep its normal TimelineDetails call using the existing project/unit parameters. A new non-resident with no property context still uses the normal landing page; do not invent a project/unit or document. Lookup failure remains different from confirmed absence.
    

    Owner label for AP Easy compatibility — 11 November 2026
    

    Quotation-only assets now use the existing AP Easy owner label. The saved field is users.assets[].userType: "owner"; the asset API returns projects[].units[].role: "owner" and projectActive.unit.role: "owner" for quotation-only cards.
    

    {
  "source": "quotation",
  "role": "owner",
  "hasQuotation": true,
  "hasUnit": false,
  "hasApeasy": false
}

    

    This is the AP Easy compatibility label. Resident features still require real unit membership. Quotation discovery does not create a CRM contact mapping, change real owner/tenant/occupant memberships, or set canUseResidentFeatures to true. Existing real-unit roles remain unchanged.
    

    Older quotation-only records using userType prospect are normalized to owner during the next successful synchronization, including a confirmed empty lookup. Only quotation placeholder records are upgraded; real-unit roles are preserved. A failed lookup performs no migration. New code must be deployed in both services before UAT acceptance; no live database backfill was run.
    

    Role is per property, not a global customer type. Quotation-only property cards use owner. Existing resident units keep the role from units.currentOccupants: owner stays owner, tenant stays tenant, and occupant stays occupant. Adding a quotation to an existing unit does not overwrite that membership role. For a non-quotation AP Easy active context, the matching saved asset role is retained; the legacy booking-only owner fallback remains when no role is saved.
    

    Pure AP Easy IDs — 11 November 2026
    

    Keep the existing AP Easy booking-list format: unmapped booking cards in projects[] return projectId: "" and unitId: "". Only new quotation-only cards use zero ID strings when unmapped. Unit and project IDs are independent: preserve a saved real projectId even when unitId is zero. New quotation records store native BSON ObjectIDs:
    

    {
  unitId: ObjectId("000000000000000000000000"),
  project: { projectId: ObjectId("000000000000000000000000") }
}

    

    The API returns hexadecimal strings. The following example is the unmapped case, where both stored IDs are zero:
    

    {
  "projectId": "000000000000000000000000",
  "projectCode": "40175",
  "units": [
    {
      "unitId": "000000000000000000000000",
      "unitNo": "A04",
      "role": "owner",
      "hasUnit": false
    }
  ]
}

    

    New quotation sync writes zero unitId explicitly for an unmapped property. The existing typed Easy active-context model keeps its legacy BSON omitempty behavior for a zero unitId and preserves the supplied projectId independently. projectActive.projectId comes from activeUnit.project.projectId; never replace a valid saved projectId with zero just because unitId is zero. Actual Smart World units keep their real IDs and membership roles. The shared zero ID must never match unrelated properties: use projectCode plus unitNo, with the existing business-key fallback for older records. A matching pure Easy booking does not turn hasUnit true. Quotation-only hasApeasy remains false until a matching booking exists; other properties' bookings cannot set it. No real unit record is created by this convention, and no live database backfill was run.
    

    Mapped project with no linked unit
    

    Keep the existing projectActive mapping: ProjectID: au.Project.ProjectID.Hex(). For example, if the project has been mapped after the AP Easy flow:
    

    {
  "projectId": "507f1f77bcf86cd799439011",
  "projectCode": "40175",
  "unit": {
    "unitId": "000000000000000000000000",
    "unitNo": "A04",
    "role": "owner",
    "hasUnit": false
  }
}

    

    The projectId above is a synthetic example of a real stored project ID. A known project does not imply resident unit membership. Keep real project IDs; use zero only when that ID is actually unmapped. Do not clear the saved projectId when unitId is zero.
    

    Quotation found: completed in green
    

    When a quotation is found for the requested property, Step 1 returns state: "completed" and colorCode: "#54C570", including before a booking exists. The quotation status label and date still describe the returned document. Without a quotation, Step 1 stays upcoming in gray (#F6F6F6) with null date/status. Existing later timeline rows and their colors are preserved.
    

    {
  "key": "quotation",
  "state": "completed",
  "colorCode": "#54C570"
}

    

    Engagement logging
    

    The backend records quotation API calls in the existing easy_detail_engagement_events collection with detailType: "quotation". Sources are profile for QuotationProfile, detail for QuotationDetails, and discovery for QuotationJourneys. Successful journey synchronization records synchronized: true and quotationCount; this covers the automatic first-login/profile-save flow through Asset Management. Mobile sends no extra log call. Logging follows each API request, including retries; it is not a unique first-login marker. Existing timeline and resident behavior remain unchanged.
