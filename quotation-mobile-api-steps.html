Mobile API connection steps

Updated 10 November 2026 · For the Smart World mobile team. Backend endpoints are implemented locally. Mobile changes, deployment, gateway checks and live UAT acceptance are pending. This HTML includes a clickable mockup with synthetic data; it sends no real requests.

1. Required journey

Not logged in → Existing login / OTP and required consent → “ฉันไม่ใช่ลูกบ้าน” → Complete profile → Save succeeds → Smart World home with the quotation timeline.

One quotation: use its exact returned reference, save purchase selection and open the timeline directly. The customer does not need to click through a quotation list.

Several quotations: ask the customer which quotation to open, then select it and show its timeline. Do not guess the newest document or first array item when several exist.

    4. Profile APIs: load suggestions, then save
    

    Send these reads alongside each other when the profile screen opens:
    

    GET /api/v1/users/me/profile
X-Token: <current-user-token>

GET /api/v1/ap-easy/QuotationProfile
X-Token: <current-user-token>
Accept: application/json

    

    QuotationProfile takes no body or query parameters. The backend uses the authenticated phone returned by token introspection. It does not require MongoDB phoneVerified: true. A booking or resident unit is not required. Example response:
    

    {
  "data": {
    "hasQuotations": true,
    "quotationCount": 1,
    "profile": {"firstName":"Jane","lastName":"Example","phoneNumber":"0800000000","email":null},
    "conflictingFields": [],
    "quotations": [{"projectNo":"P1","unitNo":"U1","quotationNo":"Q1"}]
  },
  "requestID": "crm-trace",
  "message": "Success"
}

    

    Where firstName and lastName come from
    

    CRM sends customer inside each quotation: data[].units[].quotations[].customer.
QuotationDetails keeps that object. QuotationProfile maps the four nullable fields into data.profile suggestions:

    Every field is a string or null; email: null is valid. One quotation can supply the names directly. With several quotations, different names produce null suggestions and conflictingFields: ["firstName", "lastName"]. This means CRM supplied conflicting names, not that CRM omitted customer. Ask the customer to fill the missing names. See the full customer contract and examples.
    

    Keep account values first. Use non-null suggestions only for missing fields the user has not edited. A conflicting field is null and listed in conflictingFields; ask the customer to enter it. Do not replace the account's authenticated phone or treat a quoted email as verified. Missing identity documents, photo, address and other required profile fields still come from the current account or customer input.
    

    After confirmation, use the existing profile write. Name-only example; include the other fields required by the actual form:
    

    PUT /api/v1/users/me/profile
X-Token: <current-user-token>
Content-Type: application/json

{"firstName":"Jane","lastName":"Example"}

    

    Only continue after a successful HTTP response. A failed save stays on the profile form and retains typed values. Contact changes use the existing phone/email verification flow; do not copy the entire quotation customer object into the profile write.
    

    5. After save: discover and select the exact quotation
    

    GET /api/v1/ap-easy/QuotationJourneys
X-Token: <current-user-token>

    

    The Easy response is a direct summary object, not an asset status/data wrapper. Example excerpt:
    

    {
  "hasQuotations": true,
  "hasOpenQuotations": true,
  "hasQuotationHistory": false,
  "quotationDiscovery": {"status":"available"},
  "purchaseJourneys": [{"projectNo":"P1","unitNo":"U1","quotationNo":"Q1","stage":"quotation"}],
  "activeQuotation": null
}

    

    Other journey properties remain present. The account can have a quotation even if its normal asset response has hasAssets:false. Direct Easy discovery works independently of the optional QUOTATION_DISCOVERY_ENABLED asset integration; keep normal resident assets and active-unit handling separate.
    

    If exactly one journey is returned, mobile uses that exact reference immediately. With several journeys, ask the customer to choose. Then send the flat Easy request:
    

    PUT /api/v1/ap-easy/QuotationSelection
X-Token: <current-user-token>
Content-Type: application/json

{"projectNo":"P1","unitNo":"U1","quotationNo":"Q1"}

    

    Easy validates customer access and saves users.activeQuotation, meaning the quotation currently selected by this customer. A subsequent discovery read returns root activeQuotation with the three references. This quotation path does not change resident activeUnit or membership. Wait for HTTP success before opening the timeline. A selection 403 means discovery should be refreshed. Any failure keeps the saved profile and shows purchase-entry retry; it must not fall back to another unit or document.
    

    The previously implemented asset PUT /users/me/active-unit-apeasyOnly remains an alternative when asset quotation integration is enabled. It uses a different nested body (project.projectCode, unitNo, quotationNo). For the UAT flow in this guide, use the direct Easy paths and flat body above.
    

    6. Open the Smart World timeline
    

    After successful selection, mobile sends the same project and unit. Easy reads quotationNo from the saved activeQuotation; mobile does not need to repeat it in the timeline query:
    

    GET /api/v1/ap-easy/TimelineDetails?projectNo=P1&unitNo=U1
X-Token: <current-user-token>
Accept-Language: en

    

    The timeline response is direct; data is an array of rows, not an asset-style status/data wrapper. Example quotation-only result:
    

    {
  "data": [
    {
      "key":"quotation", "label":"Quotation", "quotationNo":"Q1",
      "date":"2026-11-09T10:00:00",
      "status":{"key":"quotation_available","label":"Quotation"},
      "state":"in_progress", "colorCode":"#F9BC12"
    },
    {
      "key":"booking", "label":"Booking", "date":null, "status":null,
      "state":"upcoming", "colorCode":"#F6F6F6"
    }
  ],
  "currentStatus":{"key":"quotation_available","label":"Quotation"},
  "propertyType":"unknown", "message":"Success", "bookingLinkStatus":"not_linked"
}

    

    On Smart World home, render rows in the order returned. Quotation is Step 1 and Booking is Step 2. Use returned labels, state and colors; do not create missing contract/loan/inspection stages on the client. If the timeline read fails, show a retry state in the intended timeline destination and keep the saved profile and purchase context.
    

    The full quotation document is optional for this initial timeline view. Fetch QuotationDetails when the customer opens the document and match projectNo + unitNo + header.quotationNo inside its grouped response.
