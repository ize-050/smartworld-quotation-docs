1. Customer journey and automatic selection

Open app, not logged in → Existing login / OTP / required consent → “ฉันไม่ใช่ลูกบ้าน” → Review profile → Save succeeds → Backend selects the quotation → Smart World home shows the timeline.

The customer does not choose a quotation. The backend keeps all quotation journeys and selects one automatically. Profile completion comes before the new-customer timeline. Customers with a completed profile can refresh discovery without repeating onboarding.

Customer condition Backend action
Existing active unit, including an AP Easy unit with zero IDs Keep that unit. Select the latest quotation for the same project/unit.
No active unit Select the latest quotation overall and save its project/unit as active.
Active unit has no matching quotation Keep the unit; return activeQuotation: null. Keep the normal home.
No quotations Keep existing assets and active unit; return an empty discovery.

“Latest” uses quotationDate, not the array order, document number or update time. Valid dates rank before missing/invalid dates. Equal dates use ascending project, unit and quotation references as a stable tie-break. If all dates are missing/invalid, the same tie-break is used; this is a fallback, not a claim that one document is newer. CRM dates are returned unchanged.

    2. Profile screen: read, review and save
    

    Read the existing account and quotation customers alongside each other:
    

    GET /api/v1/users/me/profile
GET /api/v1/ap-easy/QuotationProfile
X-Token: <customer-token>

    

    QuotationProfile accepts no query parameters or body. Middleware gets the user and phone from token introspection. Mobile does not send a phone, user ID or CRM contact ID. No booking or resident unit is required. Quotation lookup does not check the MongoDB phoneVerified flag.

    Mobile does not need to send quotationNo or call QuotationSelection in this flow. The selection endpoint remains for older integrations and explicit context switches.     QuotationDetails remains optional for the full document. Match the exact triple inside data[].units[].quotations[]; it returns all documents, including each document's original customer.

    Quotation-only cards use zero ObjectIDs when no real unit/project is linked. Do not use zero IDs as unique keys: use project code plus unitNo for property cards, and the exact triple for documents. Existing resident/booking cards keep their IDs, roles and flags. Saved quotation property cards remain in the asset list during empty/unavailable lookup, with hasQuotation: false unless a successful current lookup matches them. assetCount counts unique property cards, not quotation documents. The asset endpoint keeps its existing response envelope; these fields are inside its existing data object. QuotationJourneys itself returns the JSON above at the root, without a data wrapper.
    

    The backend saves all current quotation references and one asset per property. It does not create an apEasy contact mapping before booking or replace an existing mapping. Quotation assets do not create resident membership. Enable features according to existing membership and returned capabilities, not just hasAssets.
    

    5. Empty, failed and booking states
    

    


    
Result
Mobile behavior

    
    

    
Profile save fails
Keep entered values and retry; do not open the new-customer timeline.

    

    
quotationDiscovery.status: "available", active quotation present
Open that timeline automatically.

    

    
available, activeQuotation: null
Keep the current home; quotations belong to other properties. No chooser.

    

    
empty
Successful lookup with no quotations. Keep the normal landing/home.

    

    
unavailable
Lookup is unknown. Keep saved profile/current context and offer retry. Do not show “no quotations.”

    

    
phone_verification_required
Authenticated account phone is missing/invalid. Use existing phone setup and refresh authentication.

    

    
HTTP 409 from discovery
A concurrent context switch prevented synchronization; refresh and retry.

    

    
HTTP 401/403
Follow existing authentication/error handling.

    

    

    An unavailable lookup does not clear stored quotation/asset context. A successful empty lookup clears the active quotation and current quotation snapshot while keeping existing assets and active unit. Repeated discovery is safe and does not create duplicate property assets. Discovery now synchronizes backend state even though its method remains GET; do not prefetch it as a passive suggestion request. Use QuotationProfile on the profile screen.
    

    Quotation is added before the existing property timeline. Keep every existing row and its dates, status, state, color and inspection details. For a horizontal project the usual order is Quotation → Booking → Contract → Loan → Inspection → Transfer. Vertical projects keep the existing Installment row; cash buyers keep the existing rule that omits Loan. Kafka booking-link metadata does not decide which property rows are visible. When there is no booking data yet, the normal later stages remain Upcoming with null dates/statuses. Existing currentStatus, propertyType and message are preserved when the property journey has started; before it starts, Quotation is current.
    

    CRM saves a booking and emits quotation-unit / CREATE_BOOKING; notification-service saves the contact mapping and exact booking link. Mobile does not publish Kafka events. bookingLinkStatus describes that relationship (not_linked, pending, timeline_identity_unverified or linked); a pending or unverified relationship must not hide the existing property steps.

    Send Authorization: Bearer <customer-token> to the mobile gateway. It forwards X-Token to Easy. Direct Easy paths start /api/v1/ap-easy/; existing internal /api/v1/crm-sm-detail/ aliases remain.     For the complete asset response in this guide, set QUOTATION_DISCOVERY_ENABLED=true in asset-management. With the flag off, direct Easy discovery still works, but asset discovery fields are not populated; a false asset hasQuotation must not override a successful direct discovery.
